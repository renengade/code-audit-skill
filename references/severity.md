# 定级标准

安全漏洞用 CVSS 3.1；质量与性能问题单独分级，不套 CVSS。

## 精度优先总纲

1. **不确定就降级**：数据流断链、输入可控性存疑、依赖特定环境才能触发的，一律降为「线索」或「待验证」，不写成已确认发现。
2. **误报成本模型**：一次误报消耗的信任，大于漏报一个低危问题；宁缺毋滥。
3. **blocking / non-blocking**：
   - blocking：安全漏洞、正确性缺陷（数据错误、资损、可用性）——必须处理
   - non-blocking：风格、习惯用法、文档类——仅在明显有价值时报
4. **性能项门槛**：没有测量数据（profiling / EXPLAIN / 查询次数）支撑的性能结论不写。
5. **呈现分组**：blocking 按 severity 排序必报；明显误报、吹毛求疵直接丢弃；可疑误报才写入误报节并给排除理由。

任何与本节冲突的旧表述，以本节为准。

## 一、安全漏洞等级

| 级别 | CVSS 3.1 | 判定 | 示例 |
|---|---|---|---|
| Critical | 9.0–10.0 | 未授权 RCE、全量数据泄露、可直接接管 | `eval` 接请求参数、硬编码云 AK 且有高权限 |
| High | 7.0–8.9 | 需登录的 RCE、SQLi、任意文件读写、认证绕过 | `shell=True` 拼接、JWT 可伪造 |
| Medium | 4.0–6.9 | 需较高权限或条件苛刻 | 存储型 XSS、CSRF、SSRF 探测内网 |
| Low | 0.1–3.9 | 影响有限 | 详细报错、Cookie 缺 SameSite |
| Info | 0.0 | 加固建议 | 版本泄露、日志规范 |

定级后按业务影响修正：

- 涉及资金、身份、全量用户数据的，上调一级。
- 仅影响内部测试环境、需物理接触的，下调一级。
- 无法验证可达性的，按理论级别标注 `[待验证]`，不直接上调。

## 二、CVSS 3.1 速查

基向量：`AV/AC/PR/UI/S/C/I/A`

| 指标 | 取值 | 含义 |
|---|---|---|
| AV 攻击向量 | N 网络 / A 相邻 / L 本地 / P 物理 | 越远程分越高 |
| AC 攻击复杂度 | L 低 / H 高 | 高复杂度降分 |
| PR 所需权限 | N 无 / L 低 / H 高 | 无权限最高 |
| UI 用户交互 | N 无 / R 需要 | 需要交互降分 |
| S 范围 | U 不变 / C 改变 | 改变范围升分 |
| C/I/A 机密性/完整性/可用性 | H 高 / L 低 / N 无 | 影响越大分越高 |

常见参考：

- 未授权 RCE：`AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H` = 9.8
- 需登录 SQLi：`AV:N/AC:L/PR:L/UI:N/S:U/C:H/I:H/A:N` ≈ 8.3
- 反射型 XSS：`AV:N/AC:L/PR:N/UI:R/S:C/C:L/I:L/A:N` ≈ 6.1
- 详细报错：`AV:N/AC:L/PR:N/UI:N/S:U/C:L/I:N/A:N` ≈ 5.3

> Scope 为 Changed（`S:C`）时，Base = Roundup(min(1.08 × (Impact + Exploitability), 10))；
> Scope 为 Unchanged 时为 Roundup(min(Impact + Exploitability, 10))。

无法精确计算时给出向量和近似分，并在报告中注明。

## 三、质量与性能分级

| 级别 | 质量项 | 性能项 |
|---|---|---|
| 高 | 可导致数据错误、异常吞掉安全问题 | 可被外部触发的资源耗尽、O(n²) 以上热点 |
| 中 | 明显可维护性风险、复杂度超标 | 高频路径 N+1、无界查询 |
| 低 | 命名/格式/注释 | 局部低效、可优化项 |
| 建议 | 风格统一、文档补充 | 压测/监控建议 |

质量项不进漏洞统计，单独列「质量改进项」。

## 四、状态与可信度

| 状态 | 含义 |
|---|---|
| 已确认 | 有 PoC 或完整数据流证据 |
| 待验证 | 代码可疑，但入口/权限/环境不满足验证条件 |
| 误报 | 经复核排除，需写明排除理由 |

后门/恶意代码额外用可信度：

| 可信度 | 判定 |
|---|---|
| 确认后门 | 触发条件 + 载荷 + 外联/持久化证据 |
| 高度可疑 | 混淆执行、无业务理由的外联、安装钩子 |
| 待动态验证 | 静态只能看到壳，需要沙箱运行 |
| 未发现 | 仅代表本次范围内没看到 |

## 五、报告措辞

- 已确认：`经复现，攻击者可……`
- 待验证：`代码路径显示可能……，因……未能验证，建议优先确认`
- 误报：`初筛告警为……，经确认……，判定为误报`
- 总体结论：`在本次静态审计范围内未发现确认后门，不能证明后门不存在`
